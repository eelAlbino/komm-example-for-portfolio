# Анализ исходного проекта

Исходный проект — Laravel-бэкенд для обсуждений на страницах проектов. Зафиксированы Laravel 9.52.20 и MySQL. API разделён на версии, а JWT-guard работает вместе с Laravel Policies, ролями проекта и таблицей членства. Проекты принадлежат организациям. Комментарии ссылаются на проект, автора, статус и родительский комментарий, а вложения связываются с владельцами через полиморфную таблицу Orchid. В коде также есть HTML-снапшоты со скриншотами, обложки изображений и превью видео через FFmpeg. Отдельная модель материала в выбранном контуре отсутствует.

В `Comment` запись и изменение данных обёрнуты в транзакции. `Organisation::recalcStorageSize` суммирует размеры через соединения с вложениями проектов и комментариев. `Project::includeStatistics` подготавливает статистику по комментариям и прочтению. Это наблюдения по коду, без замеров на производственных данных. В проекте есть Eloquent Events и Listeners для комментариев, вложений и организаций, очередь Laravel с database и Redis-конфигурацией, биллинговые задания, а также unit- и feature-тесты. Внешние границы включают Stripe, CloudPayments через связанный Node-сервис, трекеры задач, вебхуки проекта, FCM и почтовые провайдеры. Выбранный ZIP-контур не зависит от этих API.

## Сравнение кандидатов

| Контур | Назначение и исходные компоненты | Что посмотреть на ревью | Зависимости и сложность выделения |
|---|---|---|---|
| ZIP-выгрузка вложений комментария | `CommentController::getFilesZip`, `GetFilesZipCommentRequest`, `CommentPolicy`, `Comment::attachmentRecursive`, `AttachmentArchiveService`, `FillCommentAttachmentArchiveJob`, команда очистки и четыре тестовых файла | REST и JWT, проектные права, рекурсивный обход, полиморфные связи, повторное использование архива, DB-курсор из очереди записей о файлах, промежуточное состояние, продолжение работы и границы транзакции | Средняя. Нужны MySQL, Orchid, локальный диск, JWT, ограниченный набор моделей и database worker. Реальные внешние сервисы не участвуют. |
| Проверка виджета | `ProjectController::verifyWidget`, `WidgetService`, `ParseHtmlService`, `CheckWidgetStatusJob`, `InitCheckWidgetStatusJobs`, тесты проверки, задания и команды | HTTP-ответы и исключения, планирование повторных проверок, уникальность Job, периоды приостановки и синхронизация favicon | Средняя или высокая. Нужны проект, политика, очередь, QueueMonitor, имитация сайта клиента, отключение уведомлений Mattermost, Sentry и почты. |
| Выгрузка задач в трекеры | `ProjectIntegrationController`, `ProjectIntegration`, `Task`, `TrackerInterface`, адаптеры Jira, Trello, Kaiten и Yandex, тесты трекеров и API | Настройка интеграции, поиск внешних сущностей, экспорт задачи с вложениями, транзакционные границы, хранение параметров интеграций | Высокая. Нужны задача, комментарий, проект, политики, OAuth/токены, провайдеры и внешние ответы. Локальная проверка сквозного экспорта зависела бы от подмен внешних API. |

ZIP-выгрузка показывает полный путь от запроса до файла и его очистки. В ней можно обсудить реальные компромиссы между временем ответа, очередью и согласованностью MySQL с диском на работающем API. Для интервью начать с `AttachmentArchiveService::get` и `FillCommentAttachmentArchiveJob::handle`, затем открыть тест перехода из `filling` в `filled` и обсудить ограничения из ревью кода. Laravel 9 отличается от требования вакансии Laravel 10–11. В портфолио сохранена исходная версия.

## Текст для сопроводительного письма

В портфолио я выделил из коммерческого Laravel-проекта модуль выгрузки вложений комментариев в ZIP. В примере можно проследить проверку JWT и прав участника проекта, полиморфные связи Eloquent, переиспользование архива и продолжение сборки через очередь MySQL. В репозитории есть исходные тесты и разбор конкурентных запросов и сбоев при записи файлов.
